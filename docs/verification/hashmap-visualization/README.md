## Что проверить вручную

Frontend: http://127.0.0.1:5173/ · Java API:
http://127.0.0.1:8080/api/v1/health.

1. Запустите «Локально: split 6/7» / «Локально: split 2/7». Выберите
   TABLE_EXPANDED (кадр 9 / шаг 10): Map = 49, новая таблица = 0/128,
   старая = 31/64. На UNTREEIFIED и TREE_DIRECTION (кадры 10/11)
   старая таблица содержит 30 занятых бакетов; TRANSFER посчитан отдельно.
2. Нажмите «К проблемному кадру 11 (шаг 12)». В фокусе обе новые половины
   и временные объекты. Переключите «Показать» на «Все бакеты» и обратно;
   раскройте массив новой таблицы при необходимости. Камера не должна
   прыгать на каждом шаге. При смене операции/группы схема начинается сверху.
3. Выберите L3 (6/7) или L1 (2/7). В инспекторе переключите физическую копию,
   нажмите «К выбранному узлу», шагните назад/вперёд, в конец и обратно.
   Предпочтительный objectId восстанавливается. Переходы по next/prev/parent/L/R
   в инспекторе адресуют конкретный объект, а не логическую запись.
4. Включите «Физические связи». Доступны все пять полей, head/root snapshot,
   выбор связи клавиатурой или списком и переходы к источнику/цели.
   Подпись «вне фокуса» — продолжение реального ребра; «К цели» открывает обзор.
   Области размещения не объявляют Java-владение; `linked=false` не означает
   автоматически удалённую запись. Head/root — ссылки модели snapshot,
   не дополнительные поля Java Node.
5. В «Удаление из дерева» сравните кадры 134/135, 140/141, 153/154, 164/165
   (счётчик UI на единицу больше). Проверьте одиночные шаги в обе стороны,
   0.5×/1×/2×/4×, pause и быстрый seek. Вращения этого demo происходят при
   подготовительном treeify; для вращения удаления отдельные Java fixtures
   используют REMOVE K03 после PUT K01…K20 с hash 42. RIGHT: PUT K9…K1.
6. Измените reduced-motion в DevTools после загрузки и во время движения.
   Проверьте sidebar, zoom, ширины 412/320 px и короткий desktop. Полный
   физический граф может требовать прокрутки и 1:1; основной режим проще.

## Производительность и ограничения

[Локальная проба](performance.json) воспроизводит тяжёлый split при 97 записях
(hash 1/129), полный физический слой и playback 4×. В данной подготовке получилось
992 события, 97 видимых узлов и 384 связи. Это dev Chromium, JDK 21.0.13 и
Node 24.21.0; замер не является SLA или гарантией 60 FPS. Есть отдельные длинные
кадры; production-сборка ещё не профилировалась. Чистые decode/layout/bounds
измерены отдельно на 12 реальных trace / 1315 кадров исследования и не включают
React/SVG paint. [Проба максимального состояния](max-state.json).

На раннем варианте отдельные motion subscriptions давали p95 интервала кадра
около 133 ms; один проход SVG снизил его примерно до 33 ms в повторной пробе.
Остаются только текущая пара кадров, один progress и размеры активного trace;
нет кэша всех layout, очереди эффектов или удерживаемых выходящих SVG-кнопок.
Это ограниченная проба и проверка DOM, не доказательство отсутствия длительных утечек.

Появление/исчезновение физического объекта происходит сразу; движение существующих
узлов и изменение цвета анимируются. Seek и прерывания сразу показывают целевой
snapshot. Связи старого состояния не остаются действующими. Полный граф намеренно
плотный и открывается по запросу; in-order раскладка может требовать прокрутки.
