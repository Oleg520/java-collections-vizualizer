# Ресурсные измерения

Исторические локальные измерения от 7 ноября 2026 года. Это свидетельства для
сравнения форматов trace, а не текущий статус CI или production benchmark.
Все пять JSON сохранены: baseline полного формата, compact-профиль,
память Chromium desktop/mobile и проверка ограничений API.

[API limits](api-limits-local.json) описывает отдельную пробу с ограничителями;
её методика и результаты — в [API security](../API_SECURITY.md#проверка-ресурсов).
Профиль compact ниже получен до введения текущих rate limits: для повторения
нагрузки нужны явно повышенные лимиты **отдельного локального** backend.
Browser JSON — снимки CDP после GC, а не автоматизированный benchmark или RSS.

## Размер trace и ресурсы

Измерения выполнялись локально: WSL2 / Ubuntu 26.04, Temurin 21.0.13,
Node 24.21.0, JVM `-Xms64m -Xmx256m`. Это проверка ограниченного учебного приложения,
а не SLA или прогноз производительности Selectel VDS.

| Операция | Полный JSON до оптимизации | Компактный JSON | Оценка gzip compact |
|---|---:|---:|---:|
| Resize распределённой таблицы, 97 элементов | 4 834 937 B | 838 377 B | ~11 kB |
| Split дерева, 97 элементов, обычные длинные строки | 37 357 623 B | 1 387 103 B | ~25 kB |
| Тот же split с максимальным экранированием строк | 129 203 118 B | 3 108 893 B | ~36 kB |

В обоих вариантах большого split сохранены **990 шагов** и **96 006 вхождений узлов
в снимки**. Компактный ответ хранит **830 различных версий** вместо повторяющихся
объектов. Сокращение JSON в наиболее объёмном измеренном случае — примерно 97,6%.
Gzip в таблице рассчитан offline (уровень 9); отдельно проверено реальное HTTP gzip
Tomcat. Размеры и задержки всех сценариев сохранены в артефактах.

Нагрузочный сценарий создаёт **19 сессий**, проверяет максимальные длины и 128 записей,
выполняет **четыре больших split одновременно**, затем **192 сценария удаления из
дерева** двумя пакетами при параллелизме 4. Ошибок запросов, OOM и расхождения
состояния не было. Для повторяющихся сценариев: p50 5.18 ms, p95 7.91 ms
в данном окружении; точные значения последнего прогона — в JSON ниже.

После двух пакетов с тем же числом сессий retained Java heap измеряется через
явный GC: **15.19 → 15.21 MiB**, изменение — 11 KiB. Устойчивого накопления trace
этот эксперимент не обнаружил. Пиковый RSS процесса — около **305 MiB**; heap и RSS
различаются из-за metaspace, JIT, стека и native-памяти. Ограничение heap 256 MiB
не означает ограничение всего процесса 256 MiB. Результаты локальной пробы не определяют расход памяти в production.

После большого split и перемотки V8 used heap браузера после GC:
**~18,1 MiB desktop**, **~17,9 MiB mobile**. CDP также записывает embedder heap
(~24–25 MiB). Это не RSS всего Chromium. История ограничена 12 операциями;
полное тестирование 12 одновременно удерживаемых предельных trace не проводилось.
